# 架构决策

## ADR-001：以 JPL 轨道根数生成轨道

- 日期：2026-08-27
- 决策：使用 JPL 1800–2050 近似开普勒根数、世纪变化率和开普勒方程，而不是手工设置圆轨道与倾角。
- 原因：轨道偏心率、空间朝向、当前相位和相对周期都需要来自同一可信模型。

## ADR-002：对轨道距离作单调对数压缩

- 日期：2026-08-27
- 决策：压缩半长轴显示间距，但保留每条轨道的偏心率、倾角和方向，并在 UI 中明确标注。
- 原因：严格 AU 比例会使内行星在包含海王星的单屏画面中无法辨认。

## ADR-003：本地固定 Three.js 依赖

- 日期：2026-08-27
- 决策：将 Three.js 0.180.0、其拆分核心模块、OrbitControls 和许可证放入 `vendor/`。
- 原因：外部 CDN 可能被浏览器扩展或网络策略拦截，导致整个 ES Module 入口无法执行。

## ADR-004：CSS 负责背景，WebGL 使用透明清屏

- 日期：2026-08-27
- 决策：保留原站多层 CSS 渐变作为页面背景，Three.js Renderer 开启 alpha 并以透明色清屏。
- 原因：CSS 能逐值保留原设计背景；不透明的 `scene.background` 会完全遮挡该渐变。
